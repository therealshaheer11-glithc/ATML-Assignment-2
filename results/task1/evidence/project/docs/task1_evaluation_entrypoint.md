# Task 1 runnable evaluation and persistent evidence

This entrypoint implements the approved evaluation protocol without choosing new ML settings. Installation and CPU checks are preparation only. Actual course evaluation, reward GPU loading/memory checks and official training remain pending.

`python -m task1_dpo.evaluate --name NAME --plan` validates the complete released dataset hashes/counts, preserves ordered IDs, and exposes the fixed scopes without loading tokenizers, models or checkpoints. Names are standard, beta_003, beta_010, beta_030, length_balanced and sft. SFT is the untouched pretrained instruction model; it receives no adapter and has no paired DPO evaluation.

Real invocations require the approved GPU environment, CPU-prepared local model snapshots and an existing persistent backup root. No model downloading is allowed. Each phase uses a new output directory; existing results are never overwritten. A DPO policy must have completed its exact approved training budget and passed fresh-process reload verification. Its condition, beta, full effective configuration, dataset, selected IDs, optimizer update count and partial window must match. Reloaded base/adapter parameter hashes must equal the training record. The baseline rejects adapters.

Policy phase: load only the frozen policy, evaluate all required pairs/strata, and generate every fixed prompt in original order. Reuse the already validated evaluation calculations, response-only scoring, seed resets, decoding settings, EOS handling and global token-weighted sampled KL. Stream row-level pairs and generated text/token/log-probability records; preserve complete pool summaries after each pool. Record checkpoint file hashes, raw/effective model and generation settings, dataset membership, package versions, source/config snapshots, memory and timing. Verify policy parameters, checkpoint files, source/configuration and data hashes remain unchanged. POLICY_COMPLETE requires every pool to finish.

Reward phase: consume only matching POLICY_COMPLETE output with verified artifact hashes and full denominators. Copy the complete policy evidence into the new reward output so it survives runtime deletion. Check every saved row index, ID, message, generated token/text match and complete reward input against 4096 before loading reward weights. Stop on any input that would be shortened. Load only the frozen course 8-bit reward model using the documented, approved in-memory RoPE configuration correction. Score every response once in order, preserve row-level rewards/input lengths, and combine reward summaries with the saved policy metrics. COMPLETE requires all required scores. No policy model is loaded in this phase.

Both phases preserve FAILED records and whatever output was produced on a catchable failure. On completion or catchable failure, copy the entire phase output to a new backup folder and verify every file hash before printing BACKUP_VERIFIED. Abrupt runtime loss can interrupt this process; partial output is not a resumable completed evaluation and must not be reported as results. Release the runtime only after verified backup evidence. Phase separation allows the GPU to be released after policy generation and during preparation of reward replay. No automatic checkpoint selection, retries, budget reduction, truncation, filtering or decoding changes are introduced.

Five CPU checks use synthetic fixtures only. They cover all six plans without model/tokenizer loading, CPU refusal before output creation, baseline/checkpoint safeguards, result tampering and reward row-order rejection before loading, and verified preservation of failed partial output without success or overwriting. The Colab cell additionally checks actual released dataset plans for all six conditions and the executable help command. Synthetic checks are not PA measurements. GPU execution will be supplied in a later ready-job block after remaining launch preparation and reward-model checks.
