# Task 1 evaluation calculations and evidence

These functions implement the already approved metrics. They do not select data, checkpoints or settings and do not load course models. The runnable entrypoint will supply hash-verified full pools and final reloaded checkpoints. Actual evaluation and GPU checks remain pending.

Pair evaluation: use the same response-only summed log-probabilities and corrected DPO objective as training. Keep the complete prompt, complete supplied response and appended EOS; compare active encoding with that full sequence and stop before scoring if any content would be shortened. Score policy and adapter-disabled frozen reference in evaluation/no-gradient mode. Preserve supplied order, every row, duplicate IDs and the partial last batch. Overall and supplied-stratum metrics use strict positive reference-adjusted margins; ties remain in the full denominator. Record all four log-probabilities, margin, individual loss, correctness and response-token counts. No generated-answer KL is estimated from these supplied pairs.

Generation: use the released batch_generate helper, one prompt at a time, sampling/temperature/top-p/new-token ceiling already approved. Check the full prompt before generation and verify its returned prefix. Reset seed once per model and prompt pool, preserving fixed row order. Record inherited and effective generation configurations so checkpoint defaults remain visible; add no new decoding overrides. Save generated text/token IDs, EOS/cap indicators, prompt hash/length, token log-probabilities for policy/reference and their differences. Free full logits before scoring the reference. Sampled KL divides the global difference sum by all valid response tokens, including EOS under the course mask; finite negative estimates remain unchanged. Report population mean/SD for response lengths and preserve the released word counter and inclusive word-limit rule.

Reward replay: after releasing the policy, the runnable evaluator will use the user-approved pinned/corrected reward loader. Before scoring, verify all saved responses correspond to the original prompt order, row indices, IDs and messages, and that text matches the recorded generated tokens. The existing complete-input guard checks every prompt+answer+template before the course reward helper is called. Score all responses and average individual scalar rewards; do not deduplicate, omit, normalize or clip them. Preserve row-level reward scores and input lengths.

CPU fixtures are explicitly synthetic: tiny random Qwen weights, toy tokenizer/examples and controlled scalar rewards. Four integration checks cover strict accuracy/ties/partial batches/strata/duplicate IDs/EOS-only answers; actual tiny-model generation, repeated seed resets, unchanged weights, zero baseline KL and word-limit aggregation; reward replay membership and population averaging; and refusing overlength pair input before model scoring. They are software checks, not assignment results. Original course helpers, datasets and approved configurations are unchanged.
